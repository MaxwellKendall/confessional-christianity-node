# Confessional Christianity

A [Next.js](https://nextjs.org/) app for searching and reading the historic creeds,
confessions, and catechisms of the Reformed / Protestant tradition
(Westminster Standards, Three Forms of Unity, the Thirty-Nine Articles, and
Luther's Ninety-Five Theses), with long-form commentary and personal / family
progress tracking.

Production: <https://www.confessionalchristianity.com>

## The three surfaces

The app is three feature areas layered on one shared data model (see
[docs/DOMAIN.md](docs/DOMAIN.md) for the data model and its id conventions):

1. **Search** — an Algolia-backed search over confession text, scripture
   citations, and document/chapter/article facets.
   Entry point: [pages/index.jsx](pages/index.jsx). The free-text query is turned
   into Algolia `facetFilters` by `parseFacets` in [helpers/index.js](helpers/index.js).

2. **Reading** — statically generated (SSG) pages for each document and each
   individual entry, plus an optional markdown commentary post per entry and a
   `/study` index of those posts.
   Entry points: [pages/[confession].jsx](pages/[confession].jsx),
   [pages/[confession]/[...entry].jsx](pages/[confession]/[...entry].jsx),
   [pages/study.jsx](pages/study.jsx).

3. **Accounts** — Supabase auth plus progress tracking for yourself ("me") and
   for children (with guardian sharing via invite codes).
   Entry points: [context/AuthContext.jsx](context/AuthContext.jsx),
   [hooks/](hooks/), [pages/dashboard/](pages/dashboard/), [pages/invite/](pages/invite/).

## Data pipeline

Confession content is **build-time data**, not a database:

- `normalized-data/**/*.json` — the source of truth for confession text. Each
  file is one document: `{ content: ConfessionEntry[] }`.
- [lib/confessionContent.js](lib/confessionContent.js) statically imports those
  JSON files and builds the `contentById` map used by the reading pages. (They
  are imported, not read via `fs`, so Vercel's serverless bundles trace them —
  see the comment in that file.)
- `dataMapping/content-by-id.json` — a prebuilt flat `id -> entry` map used by
  the search-result components, regenerated by
  [scripts/populate-content-by-id.js](scripts/populate-content-by-id.js).
- The Algolia indices (`aggregate` for confession text, `citations` for
  scripture) are populated by the scripts under
  [scripts/aggregate/](scripts/aggregate/) and
  [scripts/bible-verses/](scripts/bible-verses/).
- `content/commentary/<entryId>.md` — optional long-form commentary, loaded at
  build time by [lib/commentary.js](lib/commentary.js). Scaffold a new one with
  `npm run new-post`.

Account data (progress, children, sharing) lives in Supabase; the schema is in
[supabase/migrations/](supabase/migrations/).

## Directory map

| Path | What's in it |
|---|---|
| `pages/` | Next.js routes (pages router) and API routes |
| `components/` | Shared React components for rendering results/entries |
| `lib/` | Data loaders, metadata registry, Supabase clients, analytics |
| `helpers/` | Pure functions: id parsing, facet parsing, link/title generation |
| `dataMapping/` | Document-alias lookup tables + generated `content-by-id.json` |
| `hooks/` | Supabase-backed data hooks (`useChildren`, `useMyProgress`) |
| `context/` | `AuthContext` |
| `normalized-data/` | Source confession/catechism JSON |
| `content/commentary/` | Per-entry markdown commentary posts |
| `scripts/` | Data-prep + Algolia + migration scripts |
| `supabase/migrations/` | Postgres schema for accounts |
| `test/` | Jest tests (see [docs/TESTING.md](docs/TESTING.md)) |
| `types/` | Global `.d.ts` documenting the domain shapes |

## Development

```bash
npm install
npm start          # dev server on http://localhost:1517
npm test           # jest (see docs/TESTING.md)
npm run build      # production build
npm run new-post   # scaffold a commentary post under content/commentary/
```

### Environment variables

All are `NEXT_PUBLIC_*` (client-exposed). Set them in `.env`:

- `NEXT_PUBLIC_ALGOLIA_API_KEY`, `NEXT_PUBLIC_ALGOLIA_SECRET_KEY` — search
- `NEXT_PUBLIC_ESV_API_SECRET` — ESV passage lookups (scripture text)
- `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` — auth /
  progress. If unset, [lib/supabase.js](lib/supabase.js) falls back to a no-op
  mock client so the app still builds.
- `NEXT_PUBLIC_POSTHOG_KEY`, `NEXT_PUBLIC_POSTHOG_HOST` — analytics (optional)
